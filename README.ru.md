# opencode-native-goal-tools

[English](README.md)

Три инструмента модели для встроенного Goal OpenCode: `get_goal`, `create_goal` и `replace_goal`. Цель остаётся штатной: сохраняются индикатор, проверка завершения, автоматическое продолжение и команды `/goal`.

## Требования

- Последняя стабильная версия OpenCode
- Включённый встроенный плагин `opencode.goal`
- Node.js **22.18.0+** и npm для сборки

Установка из исходников и локального архива ниже не требует публикации в npm

## Установка из исходников

Клонируйте [репозиторий](https://github.com/ex10se/opencode-native-goal-tools) или распакуйте архив исходников, затем выполните команды в его каталоге:

```sh
npm ci --ignore-scripts
npm run build
```

Добавьте каталог пакета в конфигурацию OpenCode, сохранив остальные плагины:

```jsonc
{
  "plugins": ["/absolute/path/to/opencode-native-goal-tools"]
}
```

Изменение отслеживаемой конфигурации применяется автоматически; при необходимости используйте `/reload`. Встроенная часть `./tui` загружается автоматически вместе с серверным плагином.

Пока ожидается подтверждение Goal, рядом со штатной формой отображается `Goal operation: create` или `Goal operation: replace`. Штатные кнопки и правила разрешений не меняются. Внутри generic-формы OpenCode 2.3.2 остаётся `Tool: goal`; соседняя строка уточняет операцию.

## Установка из архива пакета

Используйте архив пакета `opencode-native-goal-tools-0.1.0.tgz` из релиза или соберите его из исходников командой `npm pack`. В отдельном каталоге установки выполните:

```sh
npm install --ignore-scripts /path/to/opencode-native-goal-tools-0.1.0.tgz
```

В `plugins` укажите абсолютный путь к установленному каталогу, заканчивающийся на `node_modules/opencode-native-goal-tools`. Архив исходников GitHub не является собранным npm-пакетом; для него используйте инструкцию установки из исходников

После публикации в npm установка из реестра выполняется так:

```sh
npm install --ignore-scripts opencode-native-goal-tools@0.1.0
```

Укажите тот же путь к установленному каталогу в конфигурации. Проверка архива описана в [инструкции выпуска](docs/releasing.md)

## Использование

Попросите агента создать цель с полным описанием результата и критериями готовности. Сначала агент читает `get_goal`, затем вызывает `create_goal` по вашему явному запросу.

| Инструмент | Аргументы | Результат |
| --- | --- | --- |
| `get_goal` | `{}` | Штатное состояние или `null` |
| `create_goal` | `{ "objective": "..." }` | Проверенное штатное состояние |
| `replace_goal` | `{ "objective": "...", "expected_goal_id": "..." }` | Проверенная новая цель с новым штатным ID |

- Инструменты работают только с вызывающей сессией
- Совпадающая активная цель возвращается без изменений
- Другая существующая цель, в том числе приостановленная или завершённая, считается конфликтом
- Для явной просьбы скорректировать цель агент читает `get_goal` и передаёт её ID в `replace_goal`: активная, приостановленная или завершённая цель заменяется новой активной целью
- Устаревший ожидаемый ID отклоняется; замена не является редактированием на месте или автоматическим возобновлением приостановленной цели
- Пауза, возобновление и очистка доступны через `/goal pause`, `/goal resume`, `/goal clear`
- В Plan доступны чтение, создание и явная замена цели с проверкой разрешений хоста; это не разрешает реализацию изменений проекта
- Изменения проверяют разрешение хоста: действие `goal`, ресурс `create` или `replace`
- Собственные запросы подтверждения дополняют нативное сообщение строкой `Operation: create` или `Operation: replace`, сохраняя существующую причину. Этот hook не выдаёт разрешение. Загружайте плагин после плагинов политик, которые переписывают сообщения или меняют решение на `ask`; иначе последующие hooks могут убрать или пропустить обозначение операции
- Завершение определяет встроенный проверяющий механизм

## Ограничения

Текст содержит от 1 до 4000 единиц UTF-16 после штатной обработки внешних пробелов и кавычек. Управляющие слова `pause`, `resume`, `clear`, включая формы в кавычках, отклоняются.

Плагин сериализует собственные вызовы изменения в одной сессии. API версии 2.3.0 не предоставляет атомарной условной записи: одновременная ручная команда `/goal` может пересечься с проверкой любого из инструментов. Не меняйте цель вручную во время вызова инструмента изменения.

Ошибка запуска может произойти после сохранения цели. Сообщение об ошибке включает наблюдаемое состояние. Перед следующим действием вызовите `get_goal`; автоматический повтор не нужен.

Плагин не создаёт собственного хранилища, цикла продолжения или команды `/goal`. При конфликте имён инструментов регистрация отклоняется.

## Разработка

```sh
npm ci --ignore-scripts
npm run typecheck
npm test
npm run build
npm run test:smoke -- /path/to/opencode
npm run test:package -- /path/to/opencode
npm pack --dry-run
```

Smoke-тест сверяет версию исполняемого OpenCode с последней стабильной версией в публичном npm registry. Запускает отдельный сервер и локальную детерминированную модель с изолированными конфигурацией и базой. Проверяет вызов из активного хода, повторное создание, отказ в неявной замене, явную замену завершённой цели, отказ при устаревшем ID, создание, чтение и замену в Plan и штатное завершение в Build. Состояние цели в Plan фиксируется без предположения, что её жизненный цикл совпадает с Build. Реальные ключи провайдеров не используются. Тест печатает фактическую версию сервера и каталог диагностики, затем завершает свой сервер.
