# 0.1.0 - 2026-11-20

Published to [npm](https://www.npmjs.com/package/opencode-native-goal-tools/v/0.1.0). Known packaging defect: the TUI label described below fails to load when this version is installed under `node_modules` in OpenCode 2.3.2. The 0.1.1 build correction addresses this; these notes retain the original feature description.

Three session-scoped tools for OpenCode's native Goal:

- `get_goal` reads the current goal
- `create_goal` creates an explicitly requested goal without replacing an existing one; a matching active goal is returned unchanged
- `replace_goal` replaces an active, paused, or completed goal after an explicit correction request, using its expected native ID

The built-in indicator, completion reviewer, continuation loop, and `/goal` lifecycle controls remain native. Plan supports reading, creation, and explicit replacement, subject to host permissions. Goal management does not authorize project implementation.

Pending confirmations display `Goal operation: create` or `Goal operation: replace` beside the native TUI form. Its buttons and permission rules remain unchanged.

Objectives accept 1-4000 UTF-16 code units after native normalization. Replacement rejects stale IDs, but OpenCode 2.3.0 has no atomic conditional-write API: avoid simultaneous manual `/goal` changes. If a command fails after saving, read the current goal before taking further action; do not automatically retry.

Install from source or a built package archive using the [README](https://github.com/ex10se/opencode-native-goal-tools#readme).
